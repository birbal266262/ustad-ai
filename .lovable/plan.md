# USTAD AI app-wide futuristic mode

## Goal
Extend the existing NEW USTAD AI preference from a futuristic home into an app-wide visual mode. Preserve every route, feature, account, Guest ID, setting, API, database rule, and business workflow.

## Implementation
1. Audit all route files, shared shells, navigation, preference placement, and page-specific styling.
2. Introduce a persistent visual-mode flag using the existing client preference/storage pattern, activated only by the existing NEW USTAD AI entry.
3. Expand the scoped white digital-lab design system into shared page surfaces, controls, cards, forms, dialogs, navigation, status treatments, motion, and mobile-safe layouts.
4. Apply the mode through the shared app shell so every existing route receives the futuristic presentation without duplicating routes or business logic.
5. Add targeted page motifs for AI, coins/shop, events/tournaments, Crorepati, achievements, notifications, profile, and settings while retaining their complete existing content and behavior.
6. Keep an exit path to the classic appearance. Preserve all existing Preferences options in their current order, with NEW USTAD AI at the bottom.

## Validation
- Check every route at 360, 375, 390, 412, 430, tablet, and desktop widths.
- Verify no horizontal overflow, clipping, overlaps, dead links, console-breaking errors, or duplicate requests introduced by the visual mode.
- Exercise representative critical actions for identity/session, AI, coins/shop, events/tournaments, Crorepati, notifications, profile, settings, and language.

## Technical details
- Reuse existing route components, data hooks, state, and backend calls; no parallel app or duplicated data layer.
- Favor scoped CSS tokens and shared presentational wrappers; use lightweight CSS transitions and reduced-motion/mobile performance fallbacks.
- Route-specific adjustments will be limited to presentation where the shared shell cannot safely cover a specialized interface.
